# indextts_bases: IndexTTS をベースにした日本語 TTS のスクラッチ実装

IndexTTS2.5(T2S → S2M → ボコーダの 3 段構成のゼロショット TTS)を手本に、日本語 TTS をスクラッチで実装していく。
簡略版から始めて、実験(exp)ごとに 1 つずつ部品・条件を公式に近づけ、最終的に公式相当の実装にする。
途中で、より良さそうな構成や外部モデルへの置き換えも比べる。

## 比較の軸

| 軸 | 中身の例 | 学習し直し |
|---|---|---|
| タスク | テキストのみ / 参照音声の声で読む / 感情・抑揚の指定 | 要る(データも変わる) |
| 部品の実装 | codec・T2S・S2M・ボコーダごとに、簡略版 → 公式相当 → 新しい構成への置き換え(例: T2S を自己回帰から非自己回帰・ハイブリッドに) | その部品だけ |
| 外部モデル | 使わない / 公式と同じもの / 別のものに差し替え(例: w2v-BERT → 日本語 HuBERT、CAM++ → WavLM の話者モデル) | その部品と後段 |
| 学習の仕方 | 部品を順に学習 vs まとめて学習、事前学習 + 追加学習、事後学習(GRPO)、損失の工夫(T2S のテキスト損失、codec の音素 CTC 補助損失)、EMA、学習の長さ | 要る |
| データ | JSUT のみ → JVS → 混ぜる、量、テキストの前処理(文字 / 音素 + アクセント)、音量・無音の処理 | 要る |
| 推論の設定 | T2S のサンプリング(温度・top_p・ビームサーチ・繰り返しペナルティ)、S2M の CFG の強さ・step 数 | 要らない |
| 評価の方法 | CER → 話者類似度 → 自然さの予測 MOS → 感情の正解率・F0 など、タスクに合わせて足す | 要らない |

## ロードマップ

### フェーズ A: JSUT・テキストのみで、部品を公式相当にしていく

exp0001〜0003 で読みの正確さ(CER)は上限(元の録音 2.9%)近くまで下がったので、exp0004 以降は読み方・声の自然さを課題にする。
自然さは CER に出ず、Griffin-Lim の歪みで UTMOS も頭打ちになるので、先に自然さを測れるようにして(exp0004)から改善する(exp0005)。
最後の exp0006 で、部品・設定を公式に可能な限り近づけた構成にする。

**注記(2026-11-16 に判明)**: フェーズ A の学習データに入っている JSUT の `repeat500` は、テスト文 `voiceactress100` の 100 文を同じ話者が
5 回ずつ読んだものだった。フェーズ A の「テスト 100 文」の値は学習で見た文での値で、学習で見ていない文での値は「実用文 55 文」の方
(どの exp でも大きな差は無かったので、結果はそのままにしている。詳しくは exp0001 の README の「データ」)。

「codec と S2M を同時に学習する」は exp0006 の候補として残す)

#### 今後の課題・発展(メモ。フェーズ A の中ではやらない)

- **codebook の大きさの見直し**: 学習し直して比べたのは exp0001 の Mel のトークン・自己回帰の T2S での 1,024 と 256 の 2 点だけで、
  exp0003 以降は 256 をそのまま使っている。codebook を減らすと T2S は当てやすくなるが上限(正解のトークン → S2M)は悪くなるので、
  最適な値はその釣り合いで決まり、特徴(Mel・HuBERT・w2v-BERT)と T2S の方式で変わりうる。特にハイブリッド型は長さで時間の対応を与えるので、
  細かいトークンにも耐える可能性がある。今の一番良い構成(exp0005)で 128・512・1,024 を比べる(1 点あたり約 2.5〜3 時間)。
  また、codebook を比べた実験は exp0006 以外すべて音素の入力が前提(256 は「音素は約 40 種類なのにトークンが細かく散らばっている」
  ことから減らした値)。テキストの語彙の粒度と codebook の粒度は釣り合いで決まると考えられるので、文字の入力(公式)では
  最適な値が違う可能性がさらに高い
- (済み)長さの予測と T2S の形(自己回帰 → MaskGCT 系)の効果の切り分けは、exp0002 の結果 7 の 2 × 2 で確かめた。
  改善の大部分は T2S の形から来ていて、長さの予測は MaskGCT 系と組み合わせたときに大きく効く

### フェーズ B: 参照音声の声で読む(ゼロショットの声のクローン)

参照音声(数秒)を入力すると、その声でテキストを読む。exp の番号は 01XX。

- データ: JVS(100 人・30.25 時間、24kHz)+ JSUT。JVS の話者を「学習に使う話者」と「使わない話者」に分け、両方で評価する
  (使わない話者での成績が、ゼロショットの本当の力)
- テストの文: JVS の `parallel100` は JSUT のテスト文 `voiceactress100` と同じ 100 文なので、フェーズ A と同じ文で比べられる。
  どの話者の `parallel100` も学習に入れない(入れると、テストの文を学習で見たことになる)
- 追加する指標: 話者類似度(参照音声と合成音声の話者ベクトルの cosine 類似度。WavLM の話者照合モデルなど、
  モデルの部品に使うものとは別のモデルで測る)。CER・UTMOS・抑揚の指標はフェーズ A と同じ
- 注意: flow_matching ハンズオンの段階 3 では、学習した話者が 50 人だと聞いたことのない声に一般化しなかった。
  100 人でも同じ限界が出る可能性が高いので、学習に使った話者と使っていない話者の差も合わせて見る

### フェーズ B'(やるかは未定): 少量のデータでの話者適応

フェーズ B と別の使い方の案。参照音声 1 つでまねるのではなく、特定の 1 人の少量の録音(数分)で、フェーズ A のモデル(1 話者・軽量)を追加学習して、その人の声で読ませる。
ゼロショットのように多話者・大きいモデルにする必要がなく、推論もフェーズ A と同じなので、軽量化と両立しやすい。やるかどうかはまだ決めていない(やる場合も、フェーズ B の計画は変えない)。

- データ: JVS の 1 人あたり約 15 分(`parallel100` 約 13 分 + `nonpara30` 約 2.6 分)から、学習に使う量を変えて取る
- 比べる軸(どれも 1 つずつ変える): 学習に使う量(例: 1 分・5 分・10 分)、追加学習する部品(T2S・S2M・両方、ボコーダを含めるか)、
  追加学習の仕方(全部の重み / LoRA などの一部)、出発点のモデル(フェーズ A の 1 話者のモデル / exp0101 の多話者のモデル)
- 評価: exp0101 と同じ指標(話者類似度・CER・UTMOS・声の高さ)を、その人の本物の録音と比べる。exp0101 のゼロショットの値も比べる相手に入れる

### フェーズ C: 感情・抑揚の指定

- データ: JVNV(4 人・6 感情)+ 自動でラベルを付けたデータ(区間ごとの F0・話す速さ・音量、音声感情認識による感情)
- 指定の入れ方: 公式の感情ベクトル / テキストの間に挟むタグ、などを比べる
- 追加する指標: 感情認識の正解率、指定した F0・速さとの一致度

### 最終: 公式相当の構成

フェーズ A〜C で公式相当にした部品をまとめた構成。
