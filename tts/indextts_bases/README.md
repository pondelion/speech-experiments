# indextts_bases: IndexTTS をベースにした日本語 TTS のスクラッチ実装

IndexTTS2.5(T2S → S2M → ボコーダの 3 段構成のゼロショット TTS)を手本に、日本語 TTS をスクラッチで実装していく。
簡略版から始めて、実験(exp)ごとに 1 つずつ部品・条件を公式に近づけ、最終的に公式相当の実装にする。
途中で、より良さそうな構成や外部モデルへの置き換えも比べる。

## 比較の軸

| 軸 | 中身の例 | 学習し直し |
|---|---|---|
| タスク | テキストのみ / 参照音声の声で読む / 感情・抑揚の指定 | 要る(データも変わる) |
| 部品の実装 | codec・T2S・S2M・ボコーダごとに、簡略版 → 公式相当 → 新しい構成への置き換え(例: T2S を自己回帰から非自己回帰・ハイブリッドに) | その部品だけ |
| 外部モデル | 使わない / 公式と同じもの / 別のものに差し替え(例: w2v-BERT → 日本語 HuBERT、CAM++ → WavLM の話者モデル) | その部品と後段 |
| 学習の仕方 | 部品を順に学習 vs まとめて学習、事前学習 + 追加学習、事後学習(GRPO)、損失の工夫(T2S のテキスト損失、codec の音素 CTC 補助損失)、EMA、学習の長さ | 要る |
| データ | JSUT のみ → JVS → 混ぜる、量、テキストの前処理(文字 / 音素 + アクセント)、音量・無音の処理 | 要る |
| 推論の設定 | T2S のサンプリング(温度・top_p・ビームサーチ・繰り返しペナルティ)、S2M の CFG の強さ・step 数 | 要らない |
| 評価の方法 | CER → 話者類似度 → 自然さの予測 MOS → 感情の正解率・F0 など、タスクに合わせて足す | 要らない |

## ロードマップ

### フェーズ A: JSUT・テキストのみで、部品を公式相当にしていく

番号は、今のボトルネック(T2S)への改善効果が大きそうな順。ボコーダは音質の仕上げなので最後にする。

| exp | 基準 | 変えるもの | 狙い |
|---|---|---|---|
| [exp0001](exp0001/) | - | 簡略版で全体を動かす(Mel を量子化した codec、話者条件なしの GPT、簡略 DiT、Griffin-Lim)。テキスト入力は文字 / 音素 + アクセントの 2 通り | 基準を作る |
| exp0002 | 0001 | T2S の方式: 自己回帰 → 非自己回帰(音素の長さを予測して全トークンを並列に予測する FastSpeech2 系 / マスクを数回に分けて埋める MaskGCT 系)・ハイブリッド(音素ごとの長さ・高さのような粗い系列だけ自己回帰) | exp0001 で「音素を当てる補助の損失」(テキストのどこを読んでいるかを持たせる)が CER を 74.6% → 36.3% に下げたので、テキストと音声の時間の対応を明示的に与える方式は有望。公式(自己回帰)から離れる「別の構成との比較」の軸 |
| exp0003 | 0002 | 音声トークン: Mel の量子化 → 学習済みの自己教師ありモデル(SSL)の特徴の量子化(公式は w2v-BERT 2.0。比較に日本語 HuBERT など) | 公式との一番大きな差。exp0001 で T2S の誤りの大部分は「1 トークンずつの予測」から来ていたので、発音寄りのトークンで当てやすくなるかを見る |
| exp0004 | その時点の最新 | 学習の仕方: (1)codec と S2M を同時に学習する、(2)S2M の条件のトークンに T2S の予測を混ぜる(teacher forcing の予測 / GT に誤りを混ぜる / 発話ごとに確率で混ぜる)、(3)S2M の条件に T2S の隠れ状態を加える(音声トークンの位置の隠れ状態をトークンの埋め込みに足す IndexTTS2 の形 / テキスト部分の隠れ状態を cross-attention で入れる) | (1)codec が S2M の条件として役立つトークンを学ぶか。(2)(3)推論時に入る T2S の誤りに強い S2M にする。exp0001 で (2)(3) の一部(テキスト部分の cross-attention × 予測トークンを混ぜる学習の 2×2)を試した。T2S まで同時に学習しないのは、学習中に T2S の正解のトークンが変わり続けることと、T2S の損失が codec を当てやすい少数のトークンに崩す方向に働くため |
| exp0005 | その時点の最新 | S2M・T2S を公式相当にする: DiT の細部(U 字の skip 接続、出力側の構成など)、T2S の生成(ビームサーチ)・損失の細部、事後学習(ASR の誤り率などを報酬にした GRPO) | 公式 2.5 の構成・改良点をそろえる |
| exp0006 | その時点の最新 | ボコーダ: Griffin-Lim → スクラッチ学習の NN ボコーダ(HiFi-GAN 系) | 試聴の音質を上げる。正解 Mel から波形に戻す条件で、ボコーダ単独でも評価できる |

### フェーズ B: 参照音声の声で読む(ゼロショットの声のクローン)

- データ: JVS(100 人・30 時間)。学習に使う話者と使わない話者を分けて評価する
- 変えるもの: 話者ベクトル(公式の CAM++、または自前の話者 encoder)と、S2M の参照 Mel を入れる
- 注意: flow_matching ハンズオンの段階 3 では、学習した話者が 50 人だと聞いたことのない声に一般化しなかった。
  100 人でも同じ限界が出る可能性が高いので、学習に使った話者と使っていない話者の差も合わせて見る
- 追加する指標: 話者類似度(WavLM / CAM++ の話者ベクトルの cosine 類似度)

### フェーズ C: 感情・抑揚の指定

- データ: JVNV(4 人・6 感情)+ 自動でラベルを付けたデータ(区間ごとの F0・話す速さ・音量、音声感情認識による感情)
- 指定の入れ方: 公式の感情ベクトル / テキストの間に挟むタグ、などを比べる
- 追加する指標: 感情認識の正解率、指定した F0・速さとの一致度

### 最終: 公式相当の構成

フェーズ A〜C で公式相当にした部品をまとめた構成。

## 結果のまとめ

各 exp の結果の詳細は、それぞれの README の「結果」に書く。ここには全 exp の主な指標を並べる。
各 exp の `results/metrics.json` の形をそろえ、この表と試聴ページ(GitHub Pages)はスクリプトで作れるようにする。

| exp | 変えたもの | 読み CER(テキスト → 音声) | 備考 |
|---|---|---|---|
| exp0001 | 基準(簡略版) | 音素 73.5% / 文字 86.7%(テスト 100 文)、音素 62.5% / 文字 89.3%(実用文 55 文)。良かった条件の組み合わせで音素 21.9%(テスト 100 文) | 正解トークンからは 7.1%(元の録音 2.9%)。誤りの大部分は T2S。T2S は 2,000 step 前後から過学習し、dropout 0.3 が一番良かった。音素の補助の損失(36.3%)、codebook 256 で codec から学習し直す(50.5%)、S2M にテキストの条件 + 予測トークンを混ぜる学習、を組み合わせて 21.9% |
| exp0002 | T2S を非自己回帰に(codec・S2M は exp0001 の codebook 256) | ハイブリッド型(長さの予測 + MaskGCT 系)11.9%(テスト 100 文)・9.5%(実用文 55 文)。MaskGCT 系 19.2% / 24.3%、FastSpeech2 系 34.7% / 23.3% | 同じ codec・S2M の自己回帰 + 補助の損失は 26.3% / 26.8%。ハイブリッド型は正解トークン → S2M の上限(10.2%)にほぼ届き、長い文でも崩れない。自己回帰は長い文で後ろへ行くほど崩れる |
