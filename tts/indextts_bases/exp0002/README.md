# exp0002: T2S の方式の比較(自己回帰 → 非自己回帰)

- **基準**: exp0001(codebook 256 の codec `codec_k256` と、その codec で学習した S2M `s2m_k256`)
- **変えたもの**: T2S の方式だけ。自己回帰(GPT)→ 非自己回帰の 2 方式(FastSpeech2 系・MaskGCT 系)と、その 2 つを合わせたハイブリッド型。codec・S2M・ボコーダ・評価は exp0001 と同じものを使い回す

## 目的

exp0001 の自己回帰の T2S は、音声トークンを 1 個ずつ作り、「今テキストのどこを読んでいるか」をモデルが自分で覚えておく必要があった。
学習していない文では途中から流れを外れ、内容が崩れた(読み CER 74.6%)。「今どの音素か」を当てる補助の損失を足すと 36.3% まで
改善したので、テキストと音声の時間の対応を明示的に扱う方式は有望と考えられる。そこで、非自己回帰の 2 方式を同じ条件で比べる。

## 方式

### FastSpeech2 系(`--method duration`、`common/t2s_duration.py`)

```
テキスト(音素 + アクセント記号)→ encoder(Transformer)→ 各トークンの隠れ状態
  ├→ 長さの予測器(畳み込み 2 層)→ 各トークンが音声トークン何個分か
  └→ 長さの数だけ繰り返して並べる → decoder(Transformer)→ 全位置の音声トークンを同時に分類
```

- テキストと音声の時間の対応を、長さとして外から与える。流れを外れることが起きない
- 学習の正解の長さは、jsut-lab の音素の時刻(Julius の強制アライメント)を音声トークンの境目(42.7ms)に丸めて作る。
  pyopenjtalk の音素の並びと jsut-lab の並びが一致する発話だけを使う(JSUT 全体の 7,696 文中 7,307 文、95%)
- アクセントの記号(`#` `[` `]`)は音を持たないので長さ 0。無音・ポーズ(`^` `$` `?` `_`)は長さを持つ
- 元の FastSpeech2 の音の高さ(F0)・大きさ(energy)の予測は入れない。出力が Mel ではなく音声トークンで、
  高さ・大きさの情報もトークンに含まれるため、まず長さだけの最小の形で比べる
- 生成では各位置で一番確率の高いトークンを選ぶ(1 回の計算で全位置が決まる)

### MaskGCT 系(`--method masked`、`common/t2s_masked.py`)

```
学習: [テキスト][音声トークン(一部を [MASK] に置き換え)] → 双方向の Transformer → 隠した位置のトークンを当てる
生成: 長さを決める → 全部 [MASK] の状態から 50 回に分けて埋める
      (毎回、隠れている位置を全て予測してサンプルし、確信度の低いものを隠し直す。隠す数は回を追うごとに減らす)
```

- 公式(Amphion の `models/tts/maskgct/maskgct_t2s.py`)と同じ手順にした: 隠す割合 sin(πt/2)(下限 0.2)、
  生成は 50 回・温度 0.9・確率の上位 2% からサンプル・CFG 2.5(rescale 0.75)
- テキストと音声の時間の対応は与えず、attention で自分で見つける(全体の長さだけ与える)
- 長さ: 公式は「参照音声の 1 音素あたりの長さ × 読む文の音素数」で決める。ここは参照音声が無いので、
  学習データ全体の 1 音素あたりの長さを使う
- 公式との違い: Transformer は exp0001 の S2M と同じ DiTBlock(双方向、RoPE、時刻で LayerNorm を調整)。公式は Llama 型
  (RMSNorm を時刻で調整)で、ほぼ同じ形。参照音声を使わないので、学習でも参照音声にあたる部分は作らない。
  CFG のテキストなしの出力を学ぶため、学習で 10% の確率でテキストを除く(この確率はここで決めた値)

### 比較の基準(exp0001 の自己回帰の T2S、同じ codec・S2M)

| T2S | 読み CER(テスト 100 文、exp0001 での値) |
|---|---|
| `t2s_ph_k256`(音素入力・dropout 0.3) | 50.5% |
| `t2s_ph_k256_aux`(+ 音素の補助の損失) | 27.2% |

(exp0001 の一番良い構成は、S2M を `s2m_k256_f3` にした 21.9%。ただし `s2m_k256_f3` は自己回帰の T2S の隠れ状態と予測トークンで
学習しているので、T2S を変える exp0002 では使わず、T2S に依存しない `s2m_k256` で比べる)

## 評価の方法

exp0001 と同じ(JSUT のテスト 100 文と実用文 55 文を合成し、ASR の読み CER で測る)。`evaluate.py` の条件:

| 条件 | 中身 |
|---|---|
| `s2m_gt_tokens` | 正解トークン → S2M(この codec・S2M での上限) |
| `ar/{名前}` | exp0001 の自己回帰の T2S(比較の基準) |
| `{名前}` | 非自己回帰の T2S。長さも自分で決める(実際に使うときと同じ) |
| `{名前}/gt_length` | 分析用: 長さだけ正解を使う。長さの予測の誤りと、トークンの予測の誤りを切り分ける |

## 実行方法

```
python train_t2s.py --method duration --name t2s_duration
python train_t2s.py --method masked --name t2s_masked
python train_t2s.py --method hybrid --duration_model nar --steps 8000 --name t2s_hybrid_nar
python train_t2s.py --method hybrid --duration_model ar --steps 8000 --name t2s_hybrid_ar
python evaluate.py --runs t2s_duration t2s_masked --ar_runs t2s_ph_k256 t2s_ph_k256_aux
python evaluate.py --runs t2s_hybrid_nar t2s_hybrid_ar
```

学習は既定で 20,000 step、500 step ごとに検証し、検証 loss が一番小さい時点を保存する。
dropout は 0.3(exp0001 の自己回帰の T2S で一番良かった値にそろえる)。
学習・評価の前に、exp0001 の `runs/codec_k256`・`runs/s2m_k256`(と比較する自己回帰の T2S)を作っておく必要がある。

## 結果

### 1. 学習の経過

どちらも 20,000 step 学習したが、検証 loss は早い段階で一番小さくなり、その後は過学習した(保存したのは検証 loss が一番小さい時点)。

| T2S | 検証 loss が一番小さい step | その時点の検証の正解率 | 20,000 step での学習 / 検証の正解率 |
|---|---|---|---|
| FastSpeech2 系(`t2s_duration`) | 7,000 | 8.8%(全位置) | 34.2% / 8.4% |
| MaskGCT 系(`t2s_masked`) | 4,500 | 9.3%(隠した位置) | 87.3% / 4.1% |

MaskGCT 系は学習データをほぼ丸暗記するほど過学習した。20,000 step は長すぎ、5,000〜7,000 step で十分だった。

### 2. 読みの正確さ(ASR の CER)

`evaluate.py --runs t2s_duration t2s_masked --ar_runs t2s_ph_k256 t2s_ph_k256_aux`(結果は `results/metrics.json`)。
codec・S2M は全て `codec_k256`・`s2m_k256` で同じ。

| T2S | 方式 | テスト 100 文 | 基準との差 | 長さの比 | 実用文 55 文 | 基準との差 |
|---|---|---|---|---|---|---|
| (正解トークン → S2M、上限) | - | 10.3% | - | 1.00 | - | - |
| `ar/t2s_ph_k256` | 自己回帰 | 51.8% | +25.5pt | 0.95 | 48.8% | +22.0pt |
| `ar/t2s_ph_k256_aux` | 自己回帰 + 音素の補助の損失 | 26.3% | (基準) | 0.93 | 26.8% | (基準) |
| `t2s_duration` | FastSpeech2 系 | 34.7% | +8.4pt | 0.92 | **23.3%** | **-3.5pt** |
| `t2s_masked` | MaskGCT 系 | **19.2%** | **-7.1pt** | 0.94 | 24.3% | -2.5pt |
| `t2s_duration/gt_length` | FastSpeech2 系 + 正解の音素ごとの長さ(77 文。残りは予測) | 37.3% | +11.0pt | 0.98 | - | - |
| `t2s_masked/gt_length` | MaskGCT 系 + 正解の全体の長さ | 19.9% | -6.4pt | 1.00 | - | - |

(基準は exp0001 で一番良かった自己回帰の T2S `ar/t2s_ph_k256_aux`(同じ codec・S2M)。差は基準からのポイント差で、マイナスが改善。
自己回帰の 2 本は exp0001 の結果 7・9 と同じモデルだが、サンプリングの乱数が違うので値が 1pt 前後違う)

- **MaskGCT 系がテスト文で一番良かった(19.2%)。** 同じ S2M での自己回帰 + 補助の損失(26.3%)より 7pt 良い。
  テキストと音声の時間の対応は与えず、全体の長さだけを与えて attention で対応を見つける方式で、補助の損失も使っていない
- **実用文では FastSpeech2 系が一番良かった(23.3%)。** テスト文(34.7%)より実用文の方が良いのは、この方式だけ。
  理由は 3. の長い文の結果と関係していると考えられる
- 正解の長さを与えても良くならなかった(MaskGCT 系 19.2% → 19.9%、FastSpeech2 系 34.7% → 37.3%)。
  長さの予測は誤りの主な原因ではない。FastSpeech2 系で悪くなった理由は未確認
- 自己回帰は、補助の損失なしでは 51.8% で、非自己回帰の 2 方式はどちらもこれより大きく良い

### 3. 文の中の位置ごとの誤り率(長い文は途中から崩れるか)

exp0001 の結果 9 と同じ方法で、正解の読みを前から 4 区間に分け、区間ごとの誤り率を測った(2. で作った音声を使う)。

| T2S | テスト 100 文(1/4 → 4/4) | 実用文の長い文 4 文(1/4 → 4/4) |
|---|---|---|
| 自己回帰 + 補助の損失 | 20.6 / 22.1 / 29.5 / 33.5% | 9.3 / 46.2 / 72.3 / **93.5%** |
| FastSpeech2 系 | 24.7 / 33.6 / 42.2 / 38.5% | 17.5 / 19.4 / 28.7 / 23.7% |
| MaskGCT 系 | 19.6 / 22.9 / 21.0 / 13.0% | 44.3 / 41.9 / 45.7 / 49.5% |

- **非自己回帰の 2 方式は、長い文でも後ろで崩れない。** 自己回帰だけが、長い文で後ろへ行くほど崩れる(93.5%)。
  exp0001 では teacher forcing でも後ろほど誤りが増えたので、自己回帰で後ろの位置の予測が難しくなる理由は、
  誤りの蓄積よりも、自己回帰の T2S がテキストのどこを読んでいるかを後ろの位置ほど保てなくなることにあると考えられる(未確認)
- FastSpeech2 系は、長さとしてテキストと音声の対応を外から与えるので、長い文でも位置によらず一定の誤り率になった
- MaskGCT 系は、テスト文では後ろほどむしろ良いが、長い文では全体に誤りが多い(42〜50%)。
  学習データでほとんど見ていない長さで、attention で時間の対応を見つけることが全体的に難しくなると考えられる(未確認)

### 4. ハイブリッド型: 長さの予測 + MaskGCT 系(`--method hybrid`、`common/t2s_hybrid.py`)

2・3 で、MaskGCT 系はテスト文で一番良いが長い文で崩れ、FastSpeech2 系は長い文でも崩れなかった。そこで両方を合わせた:
テキストの encoder で音素ごとの長さを予測し、その長さで各音声トークンの位置に「その時刻の音素」の隠れ状態を並べて
[MASK] を含む音声トークンの埋め込みに足し、MaskGCT 系と同じく 50 回に分けて埋める(テキストを先頭に置く部分も残す)。
長さの予測器は 2 通り: `nar` は FastSpeech2 と同じく一度に回帰、`ar` は前のトークンの長さを入力にして 1 個ずつ分類
(0〜63 の長さ、生成は一番確率の高いもの)。どちらも 8,000 step 学習し、検証 loss は 2,000 step で一番小さくなった。
パラメータ数は `nar` 54.1M・`ar` 59.5M(MaskGCT 系 38.6M より、テキストの encoder の分だけ大きい)。

近い先行例: `nar` は NaturalSpeech 2(音素の encoder + 長さ・高さの予測を条件にした潜在拡散)、
`ar` の長さの予測は Mega-TTS 2(音素ごとの長さを自己回帰で予測するモデル)に近い。

| T2S | テスト 100 文 | 基準との差 | 長さの比 | 実用文 55 文 | 基準との差 |
|---|---|---|---|---|---|
| (正解トークン → S2M、上限。この評価で測り直した値) | 10.2% | - | 1.00 | - | - |
| `ar/t2s_ph_k256_aux`(2. の基準) | 26.3% | (基準) | 0.93 | 26.8% | (基準) |
| `t2s_masked`(2. の再掲) | 19.2% | -7.1pt | 0.94 | 24.3% | -2.5pt |
| **`t2s_hybrid_nar`** | **11.9%** | **-14.4pt** | 0.91 | **9.5%** | **-17.3pt** |
| `t2s_hybrid_ar` | 18.5% | -7.8pt | 0.78 | 10.9% | -15.9pt |
| `t2s_hybrid_nar/gt_length`(正解の音素ごとの長さ、77 文。残りは予測) | 10.3% | -16.0pt | 0.98 | - | - |
| `t2s_hybrid_ar/gt_length` | 11.8% | -14.5pt | 0.95 | - | - |

(差は基準からのポイント差。マイナスが改善)

位置ごとの誤り率(3. と同じ方法):

| T2S | テスト 100 文(1/4 → 4/4) | 実用文の長い文 4 文(1/4 → 4/4) |
|---|---|---|
| `t2s_hybrid_nar` | 17.9 / 11.2 / 11.1 / 6.9% | 6.2 / 3.2 / 0.0 / 3.2% |
| `t2s_hybrid_ar` | 21.5 / 16.3 / 20.0 / 16.0% | 7.2 / 8.6 / 8.5 / 2.2% |

- **ハイブリッド型(`nar`)がテスト文 11.9%・実用文 9.5% で、これまでで一番良かった。** 正解トークン → S2M の上限(10.2%)に
  ほぼ届き、T2S の誤りはほとんど残っていない。MaskGCT 系(19.2%・24.3%)から大きく改善した
- **長い文でも崩れない。** 長い文 4 文の誤り率は、どの区間も 0〜6%(MaskGCT 系は 42〜50%、自己回帰は後ろで 93.5%)。
  時間の対応を長さとして与えることで、MaskGCT 系の長い文の弱点がなくなった
- 長さの予測を自己回帰にした `ar` は、生成した長さが正解の 0.78 倍と短く、テスト文で `nar` より悪い(18.5%)。
  正解の長さを与えると 11.8% まで戻るので、悪化の原因は長さの予測。一番確率の高い長さを選ぶと短めになる
  (長さの分布は長い側に裾が広いので、一番確率の高い値が平均より小さい)ためと考えられる(未確認)
- テスト文では、文の前の方が誤りが多い(`nar` で 17.9% → 6.9%)。理由は未確認

### 5. 学習し直さずに確かめたこと: 測り直しのばらつき・推論の設定・長さの決め方

`analyze_inference.py`(結果は `results/inference_compare.json`)。各条件は乱数の種を決めてから合成するので、
2.〜4. の `evaluate.py` の値とは乱数の使われ方が違い、値が少し違う。

#### 測り直しのばらつき(乱数の種 0・1・2 の平均 ± 標準偏差)

| 条件 | テスト 100 文 | 基準との差 | 実用文 55 文 | 基準との差 |
|---|---|---|---|---|
| 正解トークン → S2M(上限) | 10.2 ± 0.3% | - | - | - |
| 自己回帰 + 補助の損失 | 26.8 ± 1.4% | (基準) | 27.0 ± 0.4% | (基準) |
| MaskGCT 系 | 20.7 ± 0.2% | -6.1pt | 22.8 ± 0.8% | -4.2pt |
| **ハイブリッド(長さを一度に予測)** | **11.5 ± 0.3%** | **-15.3pt** | **10.0 ± 0.7%** | **-17.0pt** |
| ハイブリッド(長さを自己回帰で予測) | 17.1 ± 1.6% | -9.7pt | 12.9 ± 0.3% | -14.1pt |

(差は基準からのポイント差。マイナスが改善)

- 測り直しのばらつきは 0.2〜1.6pt(T2S がトークンを 1 個ずつサンプルする自己回帰と、長さを自己回帰で決める版が大きい)。
  2.〜4. の条件どうしの差(6pt 以上)は、ばらつきよりずっと大きい
- ハイブリッド(長さを一度に予測)と上限の差は 1.3pt で、ばらつき(0.3pt)より大きい。T2S の誤りは少しだけ残っている

#### ハイブリッド(長さを一度に予測)の推論の設定(乱数の種 0 のみ、テスト 100 文)

| 埋める回数 | CFG の強さ | 読み CER | 既定との差 |
|---|---|---|---|
| 1(全位置を 1 回で決める) | 2.5 | 12.9% | +1.4pt |
| 5 | 2.5 | 11.8% | +0.3pt |
| 10 | 2.5 | 11.8% | +0.3pt |
| 25 | 2.5 | 10.7% | -0.8pt |
| 50(既定) | 2.5 | 11.5 ± 0.3%(上の表) | (既定) |
| 50 | 0(使わない) | 14.2% | +2.7pt |
| 50 | 1.0 | 12.0% | +0.5pt |

- **1 回で全位置を決めても 12.9% で、数回に分けて埋める効果は 1〜2pt。** FastSpeech2 系(1 回で決める、34.7%)との大きな差は、
  埋める回数ではなく、学習の仕方(一部を隠して当てる学習・テキストを先頭に置く・時刻の条件)の違いから来ている
- CFG は効いている(使わないと 14.2%、既定の 2.5 で 11.5%)

#### ハイブリッド(長さを自己回帰で予測)の長さの決め方(乱数の種 0)

| 長さの決め方 | テスト 100 文 | 長さの比 | 実用文 55 文 |
|---|---|---|---|
| 一番確率の高い値(既定) | 17.1 ± 1.6%(上の表) | 0.78 | 12.9 ± 0.3% |
| 期待値(確率で重み付けした平均を丸める) | **13.7%** | 0.87 | **9.1%** |
| サンプリング | 25.2% | 0.88 | 20.8% |

- **期待値にすると、長さが 0.78 → 0.87 倍に伸び、CER も 17.1% → 13.7% に下がった。** 「一番確率の高い値を選ぶと短めになる」ことが
  悪化の原因の一部だった。ただし期待値でも 0.87 倍で、まだ短い
- サンプリングは長さは伸びたが CER が悪くなった(25.2%)。音素ごとの長さが前後の音素とそろわず、ばらつくためと考えられる(未確認)
- 長さを一度に予測する版(長さの比 0.91)も正解より短く、試聴でも少し早口に聞こえる。log(長さ + 1) を二乗誤差で学習すると、
  予測が長さの平均より小さくなる(Jensen の不等式)ためと考えられる(実データでは未確認)

### 6. 試聴の感想(ハイブリッド型・長さを一度に予測)

- 長い文でも途中で崩れず、自己回帰(exp0001)から圧倒的に改善した。CER の結果(3.・4.)と合う
- ときどき文字を飛ばしているように聞こえる(CER では削除の誤りとして数えられているはず。内訳は未確認)
