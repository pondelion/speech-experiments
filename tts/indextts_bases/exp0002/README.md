# exp0002: T2S の方式の比較(自己回帰 → 非自己回帰)

- **基準**: exp0001(codebook 256 の codec `codec_k256` と、その codec で学習した S2M `s2m_k256`)
- **変えたもの**: T2S の方式だけ。自己回帰(GPT)→ 非自己回帰の 2 方式(FastSpeech2 系・MaskGCT 系)。codec・S2M・ボコーダ・評価は exp0001 と同じものを使い回す

## 目的

exp0001 の自己回帰の T2S は、音声トークンを 1 個ずつ作り、「今テキストのどこを読んでいるか」をモデルが自分で覚えておく必要があった。
学習していない文では途中から流れを外れ、内容が崩れた(読み CER 74.6%)。「今どの音素か」を当てる補助の損失を足すと 36.3% まで
改善したので、テキストと音声の時間の対応を明示的に扱う方式は有望と考えられる。そこで、非自己回帰の 2 方式を同じ条件で比べる。

## 方式

### FastSpeech2 系(`--method duration`、`common/t2s_duration.py`)

```
テキスト(音素 + アクセント記号)→ encoder(Transformer)→ 各トークンの隠れ状態
  ├→ 長さの予測器(畳み込み 2 層)→ 各トークンが音声トークン何個分か
  └→ 長さの数だけ繰り返して並べる → decoder(Transformer)→ 全位置の音声トークンを同時に分類
```

- テキストと音声の時間の対応を、長さとして外から与える。流れを外れることが起きない
- 学習の正解の長さは、jsut-lab の音素の時刻(Julius の強制アライメント)を音声トークンの境目(42.7ms)に丸めて作る。
  pyopenjtalk の音素の並びと jsut-lab の並びが一致する発話だけを使う(JSUT 全体の 7,696 文中 7,307 文、95%)
- アクセントの記号(`#` `[` `]`)は音を持たないので長さ 0。無音・ポーズ(`^` `$` `?` `_`)は長さを持つ
- 元の FastSpeech2 の音の高さ(F0)・大きさ(energy)の予測は入れない。出力が Mel ではなく音声トークンで、
  高さ・大きさの情報もトークンに含まれるため、まず長さだけの最小の形で比べる
- 生成では各位置で一番確率の高いトークンを選ぶ(1 回の計算で全位置が決まる)

### MaskGCT 系(`--method masked`、`common/t2s_masked.py`)

```
学習: [テキスト][音声トークン(一部を [MASK] に置き換え)] → 双方向の Transformer → 隠した位置のトークンを当てる
生成: 長さを決める → 全部 [MASK] の状態から 50 回に分けて埋める
      (毎回、隠れている位置を全て予測してサンプルし、確信度の低いものを隠し直す。隠す数は回を追うごとに減らす)
```

- 公式(Amphion の `models/tts/maskgct/maskgct_t2s.py`)と同じ手順にした: 隠す割合 sin(πt/2)(下限 0.2)、
  生成は 50 回・温度 0.9・確率の上位 2% からサンプル・CFG 2.5(rescale 0.75)
- テキストと音声の時間の対応は与えず、attention で自分で見つける(全体の長さだけ与える)
- 長さ: 公式は「参照音声の 1 音素あたりの長さ × 読む文の音素数」で決める。ここは参照音声が無いので、
  学習データ全体の 1 音素あたりの長さを使う
- 公式との違い: Transformer は exp0001 の S2M と同じ DiTBlock(双方向、RoPE、時刻で LayerNorm を調整)。公式は Llama 型
  (RMSNorm を時刻で調整)で、ほぼ同じ形。参照音声を使わないので、学習でも参照音声にあたる部分は作らない。
  CFG のテキストなしの出力を学ぶため、学習で 10% の確率でテキストを除く(この確率はここで決めた値)

### 比較の基準(exp0001 の自己回帰の T2S、同じ codec・S2M)

| T2S | 読み CER(テスト 100 文、exp0001 での値) |
|---|---|
| `t2s_ph_k256`(音素入力・dropout 0.3) | 50.5% |
| `t2s_ph_k256_aux`(+ 音素の補助の損失) | 27.2% |

(exp0001 の一番良い構成は、S2M を `s2m_k256_f3` にした 21.9%。ただし `s2m_k256_f3` は自己回帰の T2S の隠れ状態と予測トークンで
学習しているので、T2S を変える exp0002 では使わず、T2S に依存しない `s2m_k256` で比べる)

## 評価の方法

exp0001 と同じ(JSUT のテスト 100 文と実用文 55 文を合成し、ASR の読み CER で測る)。`evaluate.py` の条件:

| 条件 | 中身 |
|---|---|
| `s2m_gt_tokens` | 正解トークン → S2M(この codec・S2M での上限) |
| `ar/{名前}` | exp0001 の自己回帰の T2S(比較の基準) |
| `{名前}` | 非自己回帰の T2S。長さも自分で決める(実際に使うときと同じ) |
| `{名前}/gt_length` | 分析用: 長さだけ正解を使う。長さの予測の誤りと、トークンの予測の誤りを切り分ける |

## 実行方法

```
python train_t2s.py --method duration --name t2s_duration
python train_t2s.py --method masked --name t2s_masked
python evaluate.py --runs t2s_duration t2s_masked --ar_runs t2s_ph_k256 t2s_ph_k256_aux
```

学習は既定で 20,000 step、500 step ごとに検証し、検証 loss が一番小さい時点を保存する。
dropout は 0.3(exp0001 の自己回帰の T2S で一番良かった値にそろえる)。
学習・評価の前に、exp0001 の `runs/codec_k256`・`runs/s2m_k256`(と比較する自己回帰の T2S)を作っておく必要がある。
