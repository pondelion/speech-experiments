# exp0006: 公式の IndexTTS-2.5 に近づけた構成(フェーズ A の締め)

- **基準**: exp0005 までの自作の一番良い構成(下の「今の自作の構成」)
- **変えるもの**: 部品・設定を、公式の IndexTTS-2.5 の公開コード・設定に可能な限り近づける
- **比べるもの**: 公式に近い構成と、ここまでの自作の構成(ハイブリッド型の T2S など)。データが 10 時間と少ない条件で、公式の構成がどこまで通用するか

## 目的

フェーズ A(JSUT・テキストのみ・1 話者)の締めとして、公式の構成を部品ごとに再現し、ここまでの自作の構成と同じ評価で比べる。
話者の参照・感情の制御はフェーズ B・C で扱うので、ここでは入れない(公式でそれらを入れる場所は、空の条件か固定の値にする)。

## 調べた公式の資料

- コード: GitHub `index-tts/index-tts`(commit `d9e41aa`、2026-09-30)を `vendor/index-tts` に置いた。推論のコード(`indextts/infer_v2_5.py`)だけで、
  **学習のコードは公開されていない**(T2S・S2M・codec の損失や学習の設定はコードからは分からない)
- 設定: HuggingFace `IndexTeam/IndexTTS-2.5` の `config.yaml`(`version: 2.5`)を `vendor/indextts2.5-config` に置いた。重みはダウンロードしていない
- 論文: IndexTTS 2.5 Technical Report(arXiv:2601.03888)

公開の重みのファイルの大きさ: `gpt.pth` 3.26GB、`codec.pth` 607MB、`s2mel.pth` 415MB(他に感情の Qwen 0.6B 1.19GB)。
論文の表ではモデル全体で 0.8B。学習データは日本語 42K 時間を含む約 10 万時間(この exp は JSUT の 10 時間)。

## 公式の IndexTTS-2.5 の構成(公開コード・設定から確認したもの)

```
テキスト ── 正規化 → 日本語は MeCab(fugashi)で単語に区切って空白を入れる(漢字はそのまま)── 多言語の文字単位の tokenizer(60,509 種類)
   │
   ▼
① T2S: GPT-2(24 層、1,280 次元、20 ヘッド)。入力の先頭 = [CAM++ の話者ベクトル(192 次元)の射影 + 感情ベクトル][0 のベクトル 2 個]、
   │    テキストの埋め込みには言語の埋め込みを足す。音声トークンを 1 個ずつ生成(終わりのトークンで止まる)
   │    音声トークン(25 個/秒、8,192 種類)
   ▼
② codec の decoder: codebook のベクトル → Vocos 型の backbone(12 層、384 次元)→ 1,024 次元 → 2 倍に引き伸ばす(50 フレーム/秒)
   ▼
③ S2M: length regulator(補間 + Conv・GroupNorm・Mish)で Mel の長さ(codec の長さ × 1.72)にそろえ、
   │    参照の Mel(プロンプト)の後ろにつなげて、Flow Matching の DiT(13 層、512 次元、8 ヘッド、U 字の skip 接続 + 長い skip 接続、
   │    最後に WaveNet 8 層)で Mel を作る。CAM++ の話者ベクトル(192 次元)を条件に入れる
   │    Mel(22.05kHz、hop 256 = 86.1 フレーム/秒、80 帯域)
   ▼
④ ボコーダ: 学習済みの BigVGAN-v2(`nvidia/bigvgan_v2_22khz_80band_256x`)
```

- codec の入力は w2v-BERT 2.0 の 17 層目の特徴(全データの平均・分散で正規化、50 フレーム/秒)。stride 2 の Conv で 25 フレーム/秒に縮めてから
  Vocos 型の encoder(12 層)→ 8 次元の L2 正規化した codebook(8,192 種類、commit 0.15、codebook の損失 1.0)。復元の損失は特徴の二乗誤差
- T2S の生成の既定: サンプリング(temperature 0.8、top_p 0.8、top_k 30)、繰り返しのペナルティ 10、**ビームサーチ 3**、最大 1,500 トークン。
  長い文は 120 テキストトークンごとに区切る
- S2M の学習の損失は L1(`reg_loss_type: l1`)。プロンプトの区間は損失から除く。生成は Euler 25 step、CFG 0.7
- 論文では、S2M の backbone を U-DiT から Zipformer に替えたとある。ただし公開の設定・コードは DiT(U 字の skip 接続つき)のままなので、
  **この exp では公開コードの DiT を正とする**
- 論文から分かる学習の工夫(コードは無い): T2S の事後学習に GRPO(1 つの入力から 4 つ生成し、ASR の誤り率と話者の類似度を報酬にする。
  ASR のモデル・報酬の重みは書かれていない)、日本語の漢字の一部をランダムにカタカナの読みに置き換えて学習(推論の既定は置き換えなし)

## 今の自作の構成(exp0005 までの一番良いもの)

テキスト(pyopenjtalk の音素 + アクセント記号、50 種類)→ ハイブリッド型の T2S(音素ごとの長さを予測 + MaskGCT 系でトークンを並列に埋める、
F0 の補助の損失つき、54M)→ 日本語 HuBERT の 9 層目を量子化したトークン(23.4 個/秒、256 種類、codec 20M)→ F0 の条件つきの S2M
(DiT 8 層・512 次元、41M)→ Vocos(スクラッチで学習)。テスト 100 文で CER 5.6%、UTMOS 3.67。

## 決めたこと

- **公式どおりの版だけを作る**。自作の改良(ハイブリッド型、補助の損失、F0 の条件、音素の入力)は足さない。上の表の「△」は、公式の側だけを作る
- **Mel を公式の 22.05kHz(80 帯域、hop 256)にそろえ、S2M・ボコーダを学習し直す**。ボコーダの効果は exp0004 で分かったので、
  ボコーダ(スクラッチの BigVGAN-v2)の学習は exp0004 の設定の半分くらいの step にする
- **S2M のプロンプト・話者ベクトルは入れない**(フェーズ A は 1 話者・参照なしと決めている)。T2S の先頭の話者・感情の条件も入れない
- **大きさ(パラメータの数)は、ここまでの自作と同じくらいにする**。大きさの違いで差が出ても、構成の比較にならないため。
  構成(層の種類・つなぎ方・損失・生成の方法)は公式どおりにし、層の数・次元だけを縮める。部品ごとの目安:

| 部品 | 公式の大きさ | この exp の目安(比べる自作の部品) |
|---|---|---|
| T2S | GPT-2 24 層・1,280 次元(Transformer の部分だけで約 4.7 億、公式の語彙の埋め込み・出力層を入れて約 6.5 億) | 約 54M(今の一番良いハイブリッド型の T2S)。自己回帰の自作(exp0001・0003)は約 27M |
| codec | Vocos 型 12 層・384 次元の encoder・decoder | 約 20M(日本語 HuBERT の codec) |
| S2M | DiT 13 層・512 次元 + WaveNet 8 層 | 約 41M(今の S2M) |
| ボコーダ | BigVGAN-v2(22kHz、80 帯域) | exp0004 の BigVGAN-v2 の設定のまま(公式の大きさ) |

公式の大きさは、公式のコードの定義と `config.yaml` から計算した概算。この exp の各部品の実際のパラメータの数は、作るときに数えて記録する。

## 実装した構成

公式のコードを読んで、部品ごとに自作で実装した(`common/`)。公式の重み・コードは使わない。
動作確認で、公式の大きさの設定にすると公式と同じパラメータの数になることを確かめた(S2M: 97.8M。公式の `s2mel.pth` 415MB を float32 で数えた数とほぼ同じ。
codec: 50.6M、T2S: 約 5 億(語彙 3,000 のとき))。

| 部品 | ファイル | この exp の設定 | パラメータの数(公式の大きさのとき) |
|---|---|---|---|
| テキスト | `common/text.py` | 公式の記号の置き換え → 小文字 → MeCab(fugashi + unidic-lite)で単語に区切って空白 → 「<\|ja\|> 」を先頭に。学習では漢字を含む単語の 2 割を読み(平仮名)に置き換える | 語彙は JSUT の学習データの文字 + 平仮名(公式は 60,509 種類の多言語の文字単位の tokenizer) |
| codec | `common/codec.py`、`extract_w2v.py`、`train_codec.py` | w2v-BERT 2.0 の 17 層目(float32、JSUT の学習データで正規化)、stride 2 で 25 個/秒、ConvNeXt 12 層・192 次元・中間 1,024(公式の比 5.33 倍)、8,192 種類 | 19.0M(50.6M) |
| S2M | `common/s2m.py`、`train_s2m.py` | length regulator(Conv・GroupNorm・Mish × 4)+ DiT 13 層・320 次元・5 ヘッド(1 ヘッド 64 次元は公式と同じ)・U 字の skip + 長い skip + WaveNet 8 層、L1、Mel は正規化しない | 39.2M(97.8M) |
| T2S | `common/t2s.py`、`train_t2s.py` | GPT-2 13 層・512 次元・8 ヘッド、テキスト・音声で別々の学習する位置の埋め込み、テキストの損失 × 0.01 + 音声の損失 | 53.7M(約 5 億) |
| ボコーダ | `lib_common/neural_vocoder`(exp0004)、22.05kHz で学習し直し | BigVGAN-v2(公式の設定)、25,000 step(exp0004 の設定の半分) | - |
| Mel | `lib_common/audio.py`(`TTS_AUDIO_PROFILE=indextts22k`) | 22.05kHz、80 帯域、hop 256、上限 11.025kHz、公式の mel_spectrogram と同じ計算(端の折り返し、窓を中心に合わせない) | - |

生成の設定は公式の推論の既定のまま: T2S はサンプリング(温度 0.8、top_p 0.8、top_k 30)+ ビームサーチ 3 + 繰り返しのペナルティ 10
(transformers の generate。ビームの長さの補正 `length_penalty 0` は、今の transformers では使われないという警告が出る)、
S2M は Euler 25 step・CFG 0.7、Mel の長さ = codec の特徴のフレーム数 × 1.72。

### 公式が非公開・不明なため自分で決めたこと

- **学習の設定**(学習率・step 数・バッチ・データの扱い): 公式の学習コードは非公開なので、ここまでの自作の同じ部品と同じにした
  (codec: exp0003 の codec、S2M: exp0003 の S2M、T2S: exp0003 の自己回帰の T2S)。どれも検証データの損失が一番小さい時点を使う
- **T2S のテキストの損失の重み 0.01**: 公式のモデルはテキストの出力層も持つが、損失の重みは書かれていない。同じ UnifiedVoice の元になった
  tortoise の学習の設定の値にした
- **codec の正規化の値**: 公式は自分たちのデータで求めた w2v-BERT の特徴の平均・分散を使う。ここでは JSUT の学習データから求めた
- **語彙**: 上の表のとおり、大きさをそろえるため JSUT の文字だけにした(日本語の部分は公式と同じ 1 文字 = 1 ID)
- **損失の詰め物の扱い**: 公式どおり、T2S はバッチの詰め物を終わりの記号で埋めてそこも当てる。codec・S2M は詰め物の部分を損失から除いた

### 公式のコードで気づいた点(そのまま再現した)

- T2S の生成では、生成した音声トークンの位置の埋め込みの番号が、学習のときより 1 大きい(tortoise から引き継いだ作り)
- S2M の CFG の「条件なし」は、学習では Linear を通した後の条件を 0 にし、推論では Linear に入れる前の条件を 0 にする(推論では Linear の
  bias が残る)
- 繰り返しのペナルティは、テキストの部分に置いた仮の ID(すべて 1)にも掛かる

### 評価

exp0005 と同じ指標(テスト 100 文の CER・UTMOS・F0 の誤差・モーラの抑揚、実用文 55 文の CER・UTMOS、乱数の種 0・1・2)。
自己回帰の T2S は音素ごとの長さを出さないので、モーラの抑揚は、元の録音のモーラの区間を DTW の対応で合成音声の時間に写して測る
(`common/evaluator.py`)。比べやすいように、exp0005 の一番良い構成もこの測り方で測り直す。
