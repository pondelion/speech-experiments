# exp0005: 抑揚(イントネーション)の改善

- **基準**: exp0004 の構成(exp0003 の日本語 HuBERT のトークン + ハイブリッド型の T2S + S2M、ボコーダは Vocos)
- **変えるもの**: 抑揚に関わる部品・設定。まず原因を切り分け、効きそうな対策から試す

## 目的

exp0004 までで、読みの正確さ(CER 6%台、上限 2.9%)と声の質(UTMOS 3.5、元の録音 3.95)はほぼ解決した。
残っている問題は、ところどころで抑揚・イントネーションがおかしくなること。数値でも、TTS の F0 は元の録音から大きくずれている
(exp0004 の結果 1: GPE 22%、F0 の誤差 141 セント。正解の Mel から戻した音声は 0%・24 セント)。

## これまでの結果から分かっていること

| 経路(日本語 HuBERT のトークン) | F0 の誤差 | 出どころ |
|---|---|---|
| 正解の Mel → Vocos | 24 セント | exp0004 の結果 1 |
| 正解のトークン → S2M → Griffin-Lim | 107 セント | exp0003 の結果 3(Mel のトークンでは 48 セント) |
| テキスト → T2S → S2M → Vocos | 141 セント | exp0004 の結果 1(DTW で時間を合わせて比べた値) |

- **正解のトークンから戻しても、F0 の誤差がすでに 107 セントある。** TTS の 141 セントのうち、大部分は T2S より後ろ
  (トークンが持つ情報と S2M)で生まれている可能性が高い。ただし 107 セントはフレームをそのまま対応させた値、141 セントは DTW で
  合わせた値なので、比べ方をそろえて確かめる必要がある(分析 1)
- 日本語 HuBERT のトークンは、Mel のトークンより発音の情報が多い代わりに、F0 の情報が少ない(exp0003 の結果 3)
- S2M は音声トークンだけを条件にしていて、テキスト(アクセント記号)を見ていない。トークンに声の高さの情報が少ないと、
  S2M はアクセントを知る手段がなく、推測で高さを作るしかない
- 長さの予測は二乗誤差で学習しているので、平均的な長さに寄る。生成した音声は元の録音の 0.90 倍(少し早口)で、
  音素ごとの長さの誤差は 22.7ms(exp0004)

## 原因の仮説

| | 仮説 | どこの問題か |
|---|---|---|
| H1 | 音声トークン(日本語 HuBERT の 9 層目)に声の高さの情報が少なく、S2M が高さを推測で作るので、アクセントの位置・高さが崩れる | トークン・S2M |
| H2 | S2M がテキスト(アクセント記号)を見ていないので、トークンだけではアクセントの型(どこで上がり、どこで下がるか)が決まらない | S2M |
| H3 | S2M の Flow Matching の出発点のノイズで、高さの動きが生成のたびに変わり、ときどき不自然な形を引く | S2M(乱数) |
| H4 | T2S が、アクセントの型に合わないトークンを選ぶ(最後の回で一番確率の高いトークンを選ぶので、平均的な形に寄るなど) | T2S |
| H5 | 長さの予測が平均的で、リズムが平板・少し早口になり、イントネーションの不自然さとして聞こえる | T2S の長さの予測 |

## 切り分けの分析(学習し直さずにできるもの。まずこれを行う)

1. **どの段階で F0 がずれるか**: テスト 100 文で、次の経路の F0 の誤差・GPE を、同じ比べ方(DTW)でそろえて測る。
   正解の Mel → Vocos / 正解のトークン → S2M → Vocos / 正解の長さ + T2S → S2M → Vocos / テキスト → T2S → S2M → Vocos。
   段階ごとの増え方で、H1・H2(トークンと S2M)と H4・H5(T2S)のどちらが大きいかが分かる
2. **S2M の乱数のばらつき(H3)**: 同じトークン列を、S2M のノイズの乱数の種だけ変えて数回 Mel にし、F0 が文ごと・位置ごとに
   どれだけ変わるかを測る。ばらつきが大きいなら、S2M が高さを決めきれていない(H1・H2 の裏付けにもなる)
3. **トークンにどれだけ高さの情報があるか(H1)**: トークンから、そのフレームの F0 をどれだけ当てられるかを、簡単なモデル
   (線形・小さい MLP)で測る。Mel のトークン・日本語 HuBERT の他の層・XCodec2 と比べる
4. **アクセントの指標の見直し**: 今の「アクセント記号の前後の母音の F0 の向き」は、元の録音でも 0.71 しかなく粗い。
   アクセント句ごとの、モーラ単位の F0 の動きの形(元の録音との相関)など、元の録音で高い値になる指標に作り直す
5. **悪い例を聞く**: F0 の誤差が大きい文を選んで聞き、どこで・どう崩れているか(アクセントの位置・句の切れ目・文末)を確かめる

## 対策の案(分析の結果を見て、効きそうなものから選ぶ)

| | 対策 | 対応する仮説 | 学習し直し |
|---|---|---|---|
| A | **S2M に F0 を条件として与える**: テキスト(音素とアクセント記号)から音素ごとの F0 を予測する部品(FastSpeech2 の高さの予測にあたる)を作り、S2M の条件に加える。学習では正解の F0(元の録音から抽出)、推論では予測した F0 を使う | H1・H2 | S2M・F0 の予測器 |
| B | **S2M にテキストを条件として与える**: 音素とアクセント記号の埋め込みを、予測した長さで各フレームに並べて S2M に加える(ハイブリッド型の T2S と同じ並べ方)。exp0001 の F3(テキストの cross-attention)と比べる | H2 | S2M |
| C | **高さの情報を持つトークンにする**: 日本語 HuBERT の浅い層・Mel のトークンとの組み合わせ。XCodec2 + 固定の代表ベクトルは、F0 の情報は多い(誤差 27 セント)が、Vocos にしても声のかすれ・震えが残り UTMOS も低い(2.67、exp0004 の結果 2)ので、候補から外す | H1 | codec・S2M・T2S |
| D | **生成の設定**: T2S の温度・最後の回のサンプリング・CFG、S2M の CFG・step 数・ノイズの大きさ | H3・H4 | なし |
| E | **長さの予測を平均に寄らないものにする**: 確率的な長さの予測、または Flow Matching での予測。全体の長さの偏り(0.90 倍)も直す | H5 | T2S |

## 評価

- exp0004 の指標(CER、UTMOS、F0 の GPE・誤差、音素ごとの長さの誤差)と、分析 4 で作り直すアクセントの指標
- 1 文ずつのばらつきも見るため、主な条件は乱数の種を変えて 3 回測る
- 試聴(特に、分析 5 で選んだ悪い例)

## 結果

### 1. 切り分けの分析(`analyze_prosody.py`、結果は `results/prosody_analysis.json`、テスト 100 文)

アクセントの指標は、分析 4 で作り直した `lib_common.prosody` の 2 つ(アクセント句ごとにモーラの区間を作り、モーラの後半の F0 で比べる):

- **元の録音とのモーラの F0 の動きの相関**(主な指標): 句ごとのモーラの log F0 の並びが、元の録音とどれだけ同じ形か
- **辞書のアクセントとの一致率**: 隣り合うモーラで辞書のアクセント(pyopenjtalk の記号)の高さが変わる箇所で、F0 が同じ向きに動いている割合。
  元の録音でも 0.768 にとどまる(辞書のアクセントと話者の実際の読みの違い、F0 の推定の誤りを含むため。どちらがどれだけかは未確認)

(モーラの指標は、正解の音素ごとの長さを作れる 77 文で測る)

#### 段階ごとの F0 のずれ(分析 1)

| 経路(日本語 HuBERT のトークン、ボコーダは Vocos) | GPE | F0 の誤差 | モーラの F0 の動きの相関 | 辞書のアクセントとの一致率 |
|---|---|---|---|---|
| 元の録音 | - | - | - | 0.768 |
| s1 正解の Mel | 0.0% | 24 セント | 0.990 | 0.770 |
| s2 正解のトークン → S2M | 1.6% | 102 セント | 0.926 | 0.758 |
| s3 正解の音素ごとの長さ + T2S → S2M | 21.0% | 140 セント | 0.699 | 0.727 |
| s4 テキスト → T2S → S2M(実際に使うとき) | 22.2% | 143 セント | 0.697 | 0.734 |

(F0 は全て DTW で元の録音と時間を合わせて比べた)

- **抑揚の崩れの大部分は、T2S が選ぶトークンから来ている。** 正解のトークンから S2M で作ると、モーラ単位の F0 の動きは元の録音と
  ほぼ同じ(相関 0.926、辞書との一致率 0.758 は元の録音の 0.768 とほぼ同じ)で、F0 が 20% 以上ずれるフレーム(GPE)も 1.6% しかない。
  T2S のトークンにすると、相関が 0.70 に下がり、GPE が 21% に増える
- **長さの予測は、抑揚の崩れの主な原因ではない。** 正解の長さを与えても(s3)、長さも予測したとき(s4)とほとんど変わらない
- 正解のトークンからでも、フレーム単位の F0 の誤差は 102 セントある。ただしモーラ単位の形は保たれているので、細かい揺れ(下の分析 2)が主

#### S2M の乱数のばらつき(分析 2)

同じトークン列を、S2M の乱数の種だけ変えて 3 回 Mel にし、2 回ずつの組で F0 を比べた(長さが同じなのでフレームをそのまま対応させる)。

| トークン列 | 2 回の間の F0 の誤差 | GPE | 相関 |
|---|---|---|---|
| 正解のトークン | 80 セント | 0.3% | 0.984 |
| T2S の 1 回の生成 | 95 セント | 0.7% | 0.977 |

- S2M は同じトークン列からでも、生成のたびにフレーム単位の F0 を 80〜95 セント(1 半音弱)揺らす。正解のトークンからの誤差(102 セント)は、
  ほとんどがこの揺れの大きさ。ただし大きく外れる(GPE)ことはほとんど無く、抑揚の形を崩す原因ではない

#### トークンが持つ高さの情報(分析 3)

学習データの 500 文で「トークンの番号 → そのトークンの区間の log F0 の平均」の表を作り、テスト文の F0 を当てた(有声のトークン)。

| トークン | 相関 |
|---|---|
| Mel の codec(256 種類) | 0.671 |
| 日本語 HuBERT の 9 層目(256 種類) | 0.415 |
| XCodec2(65,536 種類) | 0.340 |

- 日本語 HuBERT のトークンは、1 個だけでは高さの情報が少ない(Mel のトークンより低い)。それでも分析 1 で正解のトークンから抑揚の形を
  再現できたのは、S2M が前後のトークンの並びから高さを推測できるためと考えられる。トークンの高さの情報の少なさ(仮説 H1)より、
  T2S がそのトークンの並びを正しく作れないこと(仮説 H4)の方が問題
- XCodec2 は種類が多すぎて、500 文では表が十分に埋まらない(1 種類あたりのデータが少ない)ので、低めに出ている可能性がある

#### 悪い例(分析 5、`results/samples/test/worst/`)

T2S から作った音声で F0 のずれが大きい 5 文は、全てカタカナの外国の固有名詞・外来語を含む文だった
(「ヴィシュヌ派の聖人、スワーミーナーラーヤン」「ウォリアーズミックスマーシャルアーツアカデミー」「ブーヒュースレーン地方」など)。
pyopenjtalk のアクセントの推定が外来語では外れやすいこと、学習データに少ない長い外来語であることが考えられる(未確認)。

#### まとめ

| 仮説 | 結果 |
|---|---|
| H1 トークンに高さの情報が少ない | 1 個のトークンでは少ないが、正解のトークンの並びからは抑揚の形を再現できる。主な原因ではない |
| H2 S2M がアクセント記号を見ていない | 正解のトークンなら問題にならない。T2S のトークンが崩れたときに、S2M が補えない原因にはなっている |
| H3 S2M の乱数 | フレーム単位で 80〜95 セント揺らすが、抑揚の形は崩さない |
| **H4 T2S のトークンの選び方** | **主な原因**(モーラの F0 の動きの相関 0.93 → 0.70、GPE 1.6% → 21%) |
| H5 長さの予測 | 抑揚の崩れの原因ではない(正解の長さでも同じ) |

### 2. 生成の設定(学習し直し不要、`sweep_inference.py`、結果は `results/sweep_inference.json`)

既定(T2S: 温度 0.9・確率の上位 2% からサンプル・CFG 2.5、S2M: CFG 0.7)から 1 つずつ変えた(テスト 100 文、乱数の種 0)。
既定は種 0・1・2 の 3 回測り、その範囲をばらつきの目安にした。

| 設定 | CER | UTMOS | GPE | モーラの F0 の動きの相関 | 辞書のアクセントとの一致率 |
|---|---|---|---|---|---|
| 既定(種 3 つの範囲) | 6.5〜7.6% | 3.51〜3.52 | 22.7〜23.6% | 0.681〜0.700 | 0.718〜0.730 |
| **T2S の CFG 0(使わない)** | 6.9% | **3.67** | **21.1%** | **0.720** | **0.736** |
| T2S の CFG 1 | 6.7% | 3.58 | 21.6% | 0.704 | 0.734 |
| T2S の CFG 4 | 7.3% | 3.42 | 24.5% | 0.661 | 0.700 |
| T2S の温度 0.5 / 1.5 | 6.4% / 7.6% | 3.52 / 3.52 | 24.5% / 23.7% | 0.683 / 0.670 | 0.726 / 0.714 |
| T2S の候補を上位 10% に | 7.2% | 3.48 | 23.4% | 0.681 | 0.718 |
| S2M の CFG 0 / 1.5 | 7.0% / 6.3% | 3.43 / 3.44 | 23.2% / 23.2% | 0.694 / 0.702 | 0.720 / 0.722 |

- **T2S の CFG を弱めるほど、抑揚と自然さが良くなった**(CFG 4 → 2.5 → 1 → 0 の順に、UTMOS 3.42 → 3.52 → 3.58 → 3.67、
  モーラの F0 の動きの相関 0.661 → 0.69 → 0.704 → 0.720)。CER はばらつきの範囲で変わらない。CFG はテキストに強く従わせる分、
  トークンの選び方が極端になり、抑揚が不自然になる方向に働いていると考えられる(未確認)。ただし改善は小さく、相関は 0.72 で、
  正解のトークンからの 0.926 には遠い
- 温度・候補の数・S2M の CFG は、ばらつきの範囲でほとんど変わらない
- 以降は T2S の CFG 0 も比べる

### 3. T2S に F0 を当てる補助の損失を足す(`train_t2s.py`・`evaluate_t2s.py`、結果は `results/evaluate_t2s.json`)

exp0001 で「今どの音素か」を当てる補助の損失が読みを大きく改善したのと同じように、T2S に「各音声トークンの区間は有声か・
声の高さ(正規化した log F0)はどれくらいか」を当てる補助の損失(重み 1.0)を足した(`t2s_f0aux`)。F0 の正解は全ての録音から
pyin で求めた(`extract_f0.py`)。それ以外の設定・S2M・Vocos は基準と同じ。乱数の種 0・1・2 の平均(± 標準偏差)。

| T2S | 生成の CFG | CER | UTMOS | GPE | F0 の誤差 | モーラの F0 の動きの相関 | 辞書のアクセントとの一致率 | 長さの比 |
|---|---|---|---|---|---|---|---|---|
| 基準 | 2.5 | 7.1 ± 0.5% | 3.52 | 23.1% | 142 セント | 0.688 ± 0.009 | 0.722 | 0.90 |
| 基準 | 0 | 6.5 ± 0.3% | 3.67 | 21.3% | 139 セント | 0.709 ± 0.011 | 0.734 | 0.90 |
| F0 の補助の損失 | 2.5 | 6.2 ± 0.1% | 3.56 | 16.3% | 136 セント | 0.795 ± 0.005 | **0.764** | 0.93 |
| **F0 の補助の損失** | **0** | **6.1 ± 0.1%** | **3.66** | **14.3%** | **130 セント** | **0.811 ± 0.004** | 0.746 | 0.93 |
| (参考)正解のトークン → S2M | - | - | - | 1.6% | 102 セント | 0.926 | 0.758 |
| (参考)元の録音 | - | 2.9% | 3.95 | - | - | - | 0.768 |

- **F0 の補助の損失で、抑揚が大きく良くなった。** モーラの F0 の動きの相関が 0.688 → 0.795(ばらつき ±0.01 よりずっと大きい)、
  GPE が 23.1% → 16.3%。辞書のアクセントとの一致率は 0.764 で、元の録音(0.768)とほぼ同じになった。T2S の中に高さの情報を持たせると、
  高さの合ったトークンを選べるようになった
- 読み(CER 7.1% → 6.2%)・自然さ(UTMOS 3.52 → 3.56)・長さ(0.90 → 0.93 倍)も少し良くなった
- 生成の CFG 0(結果 2)と組み合わせると、さらに相関 0.811・GPE 14.3%・UTMOS 3.66 になった。この exp で一番良い構成
- 正解のトークンから作ったとき(相関 0.926、GPE 1.6%)との差はまだ大きい。T2S が選ぶトークンの高さには、まだ改善の余地がある

### 4. S2M に F0 を条件として与える(`train_s2m.py`・`evaluate_s2m.py`、結果は `results/evaluate_s2m.json`)

S2M の条件(codec の decoder の特徴)に、各トークンの区間の (有声か, 正規化した log F0) を線形の層で足し(重みは 0 から)、
日本語 HuBERT の S2M から 10,000 step 追加で学習した(学習率 1e-4、exp0001 の F3 と同じ追加学習の設定。`s2m_f0cond`)。
学習では正解の F0、推論では T2S(結果 3 の F0 の補助の損失)が生成したトークン列から予測した F0(`HybridT2S.predict_f0`)を使う。
乱数の種 0・1・2 の平均。

| 条件 | CER | UTMOS | GPE | F0 の誤差 | モーラの F0 の動きの相関 | 辞書のアクセントとの一致率 |
|---|---|---|---|---|---|---|
| 正解のトークン → 元の S2M | 4.6% | 3.52 | 1.6% | 101 セント | 0.925 | 0.769 |
| **正解のトークン + 正解の F0 → F0 の条件つきの S2M** | 4.3% | 3.51 | **0.0%** | **39 セント** | **0.985** | 0.779 |
| T2S(F0 の補助の損失 + CFG 0)→ 元の S2M(結果 3) | 6.1% | 3.66 | 14.3% | 130 セント | 0.811 | 0.746 |
| **T2S + T2S が予測した F0 → F0 の条件つきの S2M** | **5.9%** | **3.70** | **11.5%** | 130 セント | **0.833** | 0.766 |

- **S2M は与えた F0 にほぼ従う。** 正解の F0 を与えると、F0 の誤差が 101 → 39 セント、モーラの F0 の動きの相関が 0.925 → 0.985 になった。
  元の S2M が生成のたびに F0 を 80〜95 セント揺らしていた(結果 1 の分析 2)のは、トークンだけでは高さが決まらないためで、F0 を与えると消える
- **T2S からの合成も良くなった**(GPE 14.3% → 11.5%、相関 0.811 → 0.833、UTMOS 3.66 → 3.70)。これがこの exp で一番良い構成
- 改善は正解の F0 のときより小さい。今の限界は T2S の F0 の予測の正確さで、F0 の予測をより正確にする(F0 を専用に予測する部品を
  作る・F0 の補助の損失の重みを変える、など)のが次の課題

### 5. F0 の補助の損失の重み(`train_t2s.py --f0_weight`・`evaluate_s2m.py --t2s`、結果は `results/evaluate_s2m.json`)

結果 4 の一番良い構成(T2S + T2S が予測した F0 → F0 の条件つきの S2M、生成の CFG 0)で、T2S の F0 の補助の損失の重みだけを変えた。

| 重み | CER | UTMOS | GPE | F0 の誤差 | モーラの F0 の動きの相関 | 辞書のアクセントとの一致率 | 長さの比 |

### 7. 外来語のアクセント(`analyze_loanword_accent.py`、結果は `results/loanword_accent.json`)

分析 5 の悪い例 5 文で、pyopenjtalk の辞書のアクセント(高・低)と、元の録音のモーラの F0 の動きを比べた。

- **読み**: 5 文のうち 4 文は、pyopenjtalk の読みが jsut-lab のラベル(録音で実際に読まれた音素)と 1 か所違った
  (「ヴィシュヌ」の「ヴィ」が b と v、「エソンヌ川」の「川」が k と g(録音は「がわ」)、「ディストリビューション」の無声化の有無、
  085 の 1 か所(外来語ではない部分))。違いは小さく、読みの大きな誤りではない。
  音素の数が同じ 3 文と、もともと一致している 1 文では、ラベルの時刻でモーラの区間を作って比べた(085 は音素の数が違うので除いた)
- **一致率**: 元の録音の F0 の動きが辞書の高・低と合っている割合は、悪い例の 4 文で 0.773(22 組)、それ以外のテスト文で 0.767(666 組)で、
  差はなかった。辞書のアクセントが全体として外れているわけではない
- **外れていたのは長いカタカナの複合語**:
  - 「ウォリアーズミックスマーシャルアーツアカデミー所属」は、辞書では 24 モーラが 1 つの句で、2 モーラ目から「所属」の前までずっと高い。
    元の録音では、途中で何度も上がり下がりしている
  - 「スワーミーナーラーヤン」は、辞書では「スワー」と「ミーナーラーヤン」の 2 つの句に分かれ、「スワー」は高 → 低、
    「ミーナーラーヤン」は低 → 高の後ずっと高い。元の録音では「スワー」で上がり、「ミーナーラーヤ」では下がり続け、最後の「ン」で上がる
  - 一致率は、辞書で高・低が変わる組だけを数えるので、こうした「ずっと高い」とされた外れは数字に出にくい
- T2S は辞書のアクセント記号を手がかりにするので、こうした語では手がかりが無いか、間違っている。改善には、外来語の複合語のアクセントの
  推定(辞書の追加・複合語の区切り)が必要で、モデルの側の問題ではない

## まとめ

- **抑揚の崩れの主な原因は、T2S が選ぶトークンだった**(結果 1)。正解のトークンからなら、元の S2M でも抑揚の形はほぼ再現できる(相関 0.93)。
  長さの予測・S2M の乱数は主な原因ではなかった
- **T2S に F0 を当てる補助の損失を足し(重み 2.0)、生成の CFG を 0 にし、S2M に T2S が予測した F0 を条件として与えると**、
  テスト文で モーラの F0 の動きの相関 0.688 → 0.838、GPE 23.1% → 10.7%、辞書のアクセントとの一致率 0.722 → 0.772(元の録音 0.768)、
  CER 7.1% → 5.6%、UTMOS 3.52 → 3.67 になった。実用文でも CER 7.7% → 6.3%、UTMOS 3.47 → 3.67
- S2M は与えた F0 にほぼ従う(正解の F0 なら相関 0.985)。**今の限界は T2S の F0 の予測の正確さ**で、正解のトークン(相関 0.93)・
  正解の F0(0.985)との差はまだある
- 悪い例は長いカタカナの複合語で、辞書のアクセント自体が手がかりにならない(結果 7)
