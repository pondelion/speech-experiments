# exp0004: NN ボコーダと、自然さの評価

- **基準**: exp0003 の日本語 HuBERT の構成(ハイブリッド型の T2S + S2M)。ボコーダは Griffin-Lim(64 回)
- **変えたもの**: ボコーダを Griffin-Lim → JSUT でゼロから学習した NN ボコーダ(HiFi-GAN V2・Vocos。BigVGAN-v2 は準備済み)。
  あわせて、自然さを測る指標(UTMOS・F0・アクセント・長さ・推論の速さ)を `tts/lib_common` に足した

## 目的

exp0001〜0003 で読みの正確さ(CER)は上限近くまで下がったが、試聴では「ロボット的な響き」「震え・ハウリングのような音」が
ずっと残っていた。Griffin-Lim は、Mel から失われた位相を繰り返しの計算(64 回)で推定するので、推定しきれない分がこの音になる。
NN ボコーダで声の質を上げ、CER に出ない自然さを測れるようにする(exp0001 の付録では、Griffin-Lim の歪みで UTMOS が
どの条件も 1.4 前後に頭打ちになり、比較に使えなかった)。

## ボコーダ(`tts/lib_common/neural_vocoder`、論文・公式の設定に合わせて自分で実装)

| ボコーダ | 生成器 | 判別器 | 損失 | パラメータ数 |
|---|---|---|---|---|
| HiFi-GAN V2 | 転置畳み込みで時間を 256 倍に引き伸ばし、各段で残差ブロックを通す(V1 の 1/4 のチャンネル) | MPD + MSD | LSGAN + feature matching × 2 + Mel の L1 × 45 | 93 万 |
| Vocos | Mel のフレームのまま ConvNeXt 8 ブロック → 各フレームの振幅と位相を予測 → 逆 STFT | MPD + MRD | hinge + feature matching + Mel の L1 × 45 | 1,346 万 |
| HiFi-GAN V1 | V2 と同じ形で、チャンネル 512 | MPD + MSD | V2 と同じ | 1,394 万(学習を途中でやめた) |
| BigVGAN-v2 | 周期的な活性化(SnakeBeta)と折り返し雑音を防ぐフィルタを組み合わせた残差ブロック(公式の 24kHz 版) | MPD + CQT の判別器 | LSGAN + feature matching × 2 + 複数の解像度の Mel の L1 × 15 | 1.12 億(未学習) |

- 入力は TTS の S2M の出力と同じ log-Mel(24kHz、80 帯域、HOP 256)。学習データは JSUT の学習データの録音から切り出す
- 各 20 万 step(HiFi-GAN V2・Vocos)、検証データ 100 文の Mel の L1 が一番小さい時点を使う(テスト文は使わない)
- HiFi-GAN V1 は 1 step 0.23 秒で 20 万 step に約 13 時間かかり、先に学習した Vocos が V2 を大きく上回っていた
  (検証の Mel の L1: Vocos 0.154、V2 0.386)ので、途中でやめた。BigVGAN-v2 は 1 step のデータを 2 × 32,768 サンプル
  (公式は 4 × 65,536。GPU に収まるように変える)、5 万 step で約 12 時間の見込みで、これから学習する

## 評価の方法(`evaluate.py`、指標は `tts/lib_common/prosody.py`・`mos.py`)

| 条件 | 中身 |
|---|---|
| `real` | 元の録音(上限) |
| `copy/{ボコーダ}` | 正解の Mel → ボコーダ(ボコーダ単独の性能) |
| `tts/{ボコーダ}` | テキスト → T2S → S2M の Mel → ボコーダ。Mel は 1 回だけ作り、全てのボコーダで同じものを使う(違いはボコーダだけ) |

(`tts/` の Mel は、exp0003 と同じモデル(日本語 HuBERT の codec・ハイブリッド型の T2S・S2M)で作り直した、別の 1 回の生成。
T2S と S2M は生成のたびに乱数を使うので、exp0003 の音声とは同じにならず、CER も乱数のばらつきの分だけ違う
(Griffin-Lim でテスト文 6.4%・実用文 6.2%。exp0003 では 6.9%・5.9%)。exp0003 と全く同じ乱数の流れは、同じプロセスで先に動かした
自己回帰の構成のモデルを片付けで消したので、再現できない)

| 指標 | 中身 |
|---|---|
| CER | 読みの正確さ(ASR の読みの文字誤り率) |
| UTMOS | 人が付ける自然さの点数(1〜5)の推定 |
| F0 の GPE・誤差 | 声の高さの再現度。GPE = 両方が有声のフレームのうち F0 が 20% 以上ずれた割合、誤差 = それ以外のフレームの誤差(セント、100 セント = 半音)。TTS は長さが違うので、Mel の近さで DTW により時間を合わせて比べる |
| アクセントの正しさ | pyopenjtalk のアクセント記号の前後の母音の F0 が、正しい向きに動いている割合(「[」で上がる、「]」で下がる)。音素の区間は、元の録音・`copy` は jsut-lab の時刻、`tts` は T2S が予測した長さ |
| 音素ごとの長さの誤差 | T2S が予測した長さと jsut-lab の正解の差(ボコーダに依らない) |
| 推論の速さ | RTF = 生成時間 / 音声の長さ(GPU、CPU は 4 スレッド) |

## 結果

### 1. ボコーダの比較(テスト 100 文)

| 条件 | CER | UTMOS | 基準との差 | F0 の GPE | F0 の誤差 | アクセントの正しさ |
|---|---|---|---|---|---|---|
| 元の録音 | 2.9% | 3.95 | - | - | - | 0.711 |
| 正解 Mel → Griffin-Lim(基準) | 3.0% | 1.40 | (基準) | 3.5% | 20 セント | 0.722 |
| 正解 Mel → HiFi-GAN V2 | 3.4% | 3.42 | +2.02 | 0.0% | 35 セント | 0.715 |
| **正解 Mel → Vocos** | 3.2% | **3.53** | **+2.13** | **0.0%** | 24 セント | 0.709 |
| TTS → Griffin-Lim(基準) | 6.4% | 1.43 | (基準) | 23.4% | 141 セント | 0.680 |
| TTS → HiFi-GAN V2 | 6.4% | 3.50 | +2.07 | 21.6% | 142 セント | 0.681 |
| **TTS → Vocos** | 6.3% | **3.54** | **+2.12** | 21.7% | 141 セント | 0.684 |

実用文 55 文(TTS のみ): CER Griffin-Lim 6.2%・HiFi-GAN V2 7.3%・Vocos 7.7%、UTMOS 1.55・3.45・3.47。
(UTMOS の差は基準からの差で、プラスが改善)

- **NN ボコーダで UTMOS が 1.4 → 3.5 に上がった(元の録音 3.95)。** 試聴でも、これまでずっと残っていたロボット的な響きや
  震え・ハウリングのような音がなくなった。exp0001 の付録で UTMOS が頭打ちだったのは Griffin-Lim の歪みのためで、
  NN ボコーダにすれば UTMOS で自然さを比べられるようになった
- **Vocos が HiFi-GAN V2 より少し良い**(UTMOS 3.53 対 3.42、F0 の誤差 24 対 35 セント)。どちらも 20 万 step で、
  論文(200 万 step 以上)よりかなり短い学習
- CER はボコーダでほとんど変わらない(読みの正確さは T2S・S2M で決まっている)。実用文では NN ボコーダの方が 1pt 前後悪いが、
  原因は未確認
- **TTS の F0 は、ボコーダに依らず元の録音から大きくずれている**(GPE 22%・誤差 141 セント。正解 Mel からは 0〜3.5%・20〜35 セント)。
  TTS の Mel そのものの抑揚が元の録音と違うためで、次の exp0005(抑揚のモデル化)の課題
- 音素ごとの長さの誤差は 22.7ms、生成した音声の長さは元の録音の 0.90 倍(少し早口)。これも exp0005 の課題
- アクセントの正しさは、元の録音でも 0.711 と低く、TTS(0.68)との差が小さい。音素の区間を jsut-lab の時刻で決めても
  アクセントの向きの通りに F0 が動いていない箇所が 3 割あり、指標として粗い(アクセント句の境目での声の高さの下がり方などの影響と
  考えられる。未確認)。改善を測るには、区間の決め方や比べ方を見直す必要がある

### 2. exp0003 の外部のコーデックの構成も Vocos で戻す(`vocode_exp0003.py`)

exp0003 では、XCodec2(固定の代表ベクトル)・BiCodec は CER が日本語 HuBERT より良かったが、聞くと声がかすれる・震えるような
違和感があった。それが Griffin-Lim のせいだったかを切り分けるため、同じ TTS の Mel を Griffin-Lim と Vocos で戻した
(Mel は作り直した別の 1 回の生成なので、CER は exp0003 の値と乱数のばらつきの分だけ違う)。

| 構成(ハイブリッド型 + S2M) | ボコーダ | テスト 100 文の CER | UTMOS | 実用文 55 文の CER | UTMOS |
|---|---|---|---|---|---|
| 日本語 HuBERT(上の表) | Griffin-Lim | 6.4% | 1.43 | 6.2% | 1.55 |
| 日本語 HuBERT(上の表) | **Vocos** | 6.3% | **3.54** | 7.7% | **3.47** |
| XCodec2(固定の代表ベクトル) | Griffin-Lim | 5.0% | 1.37 | 6.0% | 1.45 |
| XCodec2(固定の代表ベクトル) | Vocos | 5.1% | 2.67 | 6.1% | 2.80 |
| BiCodec | Griffin-Lim | 5.7% | 1.40 | 5.0% | 1.51 |
| BiCodec | Vocos | 5.6% | 3.05 | 7.1% | 3.07 |

- **Vocos にしても、外部のコーデックの構成は日本語 HuBERT より UTMOS が低い**(XCodec2 2.67・BiCodec 3.05、日本語 HuBERT 3.54)。
  Griffin-Lim ではどれも 1.4 前後で差が見えなかった。exp0003 で聞こえた違和感の原因は、Griffin-Lim だけではなく、
  トークン・S2M の側にもある(1 秒あたりのトークン数が多く、S2M の条件がトークンの埋め込みであることなどが考えられる。未確認)
- 試聴でも、Vocos にしても XCodec2・BiCodec の声のかすれ・震え(喉を痛めた人が話しているような感じ)は直らなかった
- CER はボコーダでほとんど変わらない(実用文の BiCodec だけ 5.0% → 7.1% と悪くなったが、原因は未確認)

### 3. 推論の速さ(RTF。1 秒の音声を作るのにかかる秒数)

| ボコーダ | GPU | CPU(4 スレッド) |
|---|---|---|
| Griffin-Lim(64 回) | 0.029 | 0.014 |
| HiFi-GAN V2 | 0.0015 | 0.025 |
| **Vocos** | **0.0005** | **0.0063** |

- **Vocos は GPU・CPU とも一番速い**(GPU で Griffin-Lim の約 60 倍、CPU で約 2 倍)。Mel のフレームのまま計算し、最後に逆 STFT を
  1 回するだけなので軽い。推論の最適化(`tts/inference_optimization`)のブラウザで動かす目標にも向く
- HiFi-GAN V2 はパラメータ数が少ない(93 万)が、波形のサンプル単位まで畳み込みで引き伸ばすので、CPU では Vocos の 4 倍遅い
- Griffin-Lim は GPU の方が CPU より遅かった。短い計算を 64 回順に繰り返すので、GPU に処理を渡す手間の方が大きいと考えられる(未確認)

## 実行方法

```
python train_vocoder.py --model vocos --steps 200000 --name vocos
python train_vocoder.py --model hifigan_v2 --steps 200000 --name hifigan_v2
python train_vocoder.py --model bigvgan_v2 --steps 50000 --name bigvgan_v2
python evaluate.py --vocoders vocos hifigan_v2
```

## コードの構成

```
tts/lib_common/
├── neural_vocoder/   NN ボコーダ(hifigan.py・vocos.py・bigvgan.py と、学習の設定・損失・読み込み)
├── prosody.py        抑揚の評価(F0 の比較・DTW、アクセントの正しさ、音素ごとの長さの誤差)
exp0004/
├── train_vocoder.py  ボコーダの学習(1 万 step ごとに検証データの 1 文を runs/{名前}/samples/ に残す)
├── evaluate.py       評価
├── vocode_exp0003.py exp0003 の外部のコーデックの構成の TTS を、Griffin-Lim と Vocos で比べる
└── README.md         このレポート
```
